# Model tutorials: every model, from the basics up

One notebook per model, ordered from the simplest to the most complex. Each notebook follows the same plan:

1. **the idea in words**;
2. **the background and the equations**, with every symbol explained;
3. **the model built from scratch** on a tiny example (numpy or PyTorch), step by step, and checked against our code;
4. **the same model from our code** (`src/ml/`) on the toy CCD world;
5. **when to use it** (and when not), and things to try.

They pair with the learning guide [`docs/overleaf_ml_guide/ml_guide.tex`](../../docs/overleaf_ml_guide/ml_guide.tex): each
notebook names its guide section, and the notation is the same.

**Without amplifier labels.** Wherever our code is used on the toy CCD, the models see each amplifier's own traces, not which
amplifier it is. Notebook 09 shows why this works. The exceptions are the comparisons in 09 and 09b, which run the labelled version (A+B) next to the label-free one.

**The toy CCD world** (`src/ml/synthetic.py`) simulates packets with realistic noise, but its physics is invented: the numbers compare
methods, they say nothing about the real CCD. Real data go through level 1 ([`lvl1/`](../../lvl1/README.md)).

## Running them

Every notebook is saved with its outputs, so it can be read without running it. To rerun (a few minutes each, with `.venv`):

```bash
cd notebooks/model_tutorials
../../.venv/bin/jupyter execute --inplace 05_gaussian_processes.ipynb      # or open it in Jupyter
```

The notebooks are generated by `make_tutorials.py` from `tutorials_part1.py` (00–05) and `tutorials_part2.py` (06–14, 09b); edit those and rerun
`../../.venv/bin/python make_tutorials.py` to change them. `tutorial_utils.py` holds the three shared helpers: `toy_scan`, `grouped_cv` and
`report`.
